# Notae

**Notae** — генератор учебных презентаций: вы пишете сценарий обычным текстом
(просто список слайдов, строк, субтитров и задержек), а скрипт собирает из него
готовые видео слайдов и цельный фильм.

Внутри используется [Manim Community](https://www.manim.community/): слайды
рисуются в LaTeX-шрифте (кириллица — PT Serif, формулы — Computer Modern),
с центрированием и заголовком ярко-жёлтого цвета.

---

## 1. Что нужно

- Python 3.9+
- [Manim Community](https://www.manim.community/) (`pip install manim`)
- `ffmpeg` (для склейки; обычно ставится вместе с Manim)
- LaTeX: MiKTeX (Windows) или TeX Live, с пакетами `amsmath`, `amssymb`,
  `amsthm`, `xcolor`, `paratype` (PT Serif)
- Для старого `.doc` (не `.docx`) — любой из `antiword`, `catdoc` или
  LibreOffice. Для `.docx` ничего дополнительного не нужно.

Установка Manim:

```bash
pip install manim
```

---

## 2. Быстрый старт

1. Откройте файл `scenario.tex` (он уже лежит рядом с `build.py`) и
   отредактируйте его. Вместо него можно положить свой сценарий —
   `txt`, `md`, `tex`, `docx` или `doc`.
2. Запустите:

```bash
python build.py
```

(На Windows удобнее запускать из терминала. Двойной щелчок по файлу,
скачанному ZIP-архивом, может вызвать предупреждение Windows — см. ниже.)

3. Скрипт спросит, что сгенерировать (видео, PDF или оба), а затем — про
   продолжение предыдущей компиляции видео:

```
Что сгенерировать?
  1 — видео
  2 — PDF
  3 — и видео, и PDF
Выбор (1/2/3) [3]:

Продолжить предыдущую компиляцию? (y/n):
```

- **1** — только видео;
- **2** — только PDF;
- **3** — и видео, и PDF (PDF собирается параллельно с видео);
- **y** — продолжить: уже готовые слайды из `media/slides/` сохраняются,
  доделываются только недостающие. Удобно, если прошлая сборка прервалась;
- **n** — собрать видео заново: папка `media/slides/` очищается.

4. В конце скрипт выведет, что готово:

```
============================================================
  Готово!
  Слайды: .../media/slides
  Видео:  .../media/final.mp4
  PDF:    .../media/handout.pdf
  LaTeX:  .../media/handout.tex
============================================================
```

Скрипт **не удаляет сам себя** и не трогает файл сценария.
По завершении окно не закрывается сразу — скрипт попросит нажать Enter.

## 3. Результат

```
media/
  slides/            ← Title.mp4 (если есть титульный слайд),
                       Slide00.mp4, Slide01.mp4, ... (по одному видео на слайд)
  final.mp4          ← все слайды, склеенные по порядку
  handout.tex        ← LaTeX-исходник PDF-версии (если запрошена)
  handout.pdf        ← PDF-версия (если удалось собрать)
```

Слайды рендерятся **параллельно, не более 5 одновременно**.
Все промежуточные файлы (`_scenes.py`, `_work/`, `__pycache__/`, LaTeX-кэш)
после сборки удаляются — остаются только результаты в `media/`.

### PDF-версия (необязательно)

PDF — это «раскадровка» презентации: одна страница на каждое состояние
слайда (после добавления или удаления строки; титульный слайд — отдельной
страницей). **Субтитры в PDF не включаются.** Оформление повторяет видео:
страница 16:9, заголовок сверху, строки по центру оставшейся области, тёмный
фон, PT Serif, жирный жёлтый заголовок, формулы Computer Modern; размеры
подобраны так же, как в кадре (заголовок 44 pt, строки 36 pt).

Компилятор выбирается так:

- если на компьютере есть локальный LaTeX (`pdflatex` / `xelatex` /
  `lualatex`), PDF собирается локально — **без сети**;
- иначе скрипт предупредит, что для PDF нужен доступ к сети и что текст
  презентации будет отправлен на сторонний сервер `latexonline.cc`
  (конфиденциальность не гарантируется), и спросит согласие;
- при отказе или ошибке онлайн-компиляции остаётся `media/handout.tex` —
  его можно скомпилировать где угодно (Overleaf, локальный TeX, онлайн).

Исходник `handout.tex` сохраняется всегда, когда запрошен PDF: из него
получается ровно тот же PDF.

## 4. Файл сценария

Скрипт сам находит сценарий в своей папке. Поддерживаются расширения:

| Расширение | Как читается |
|---|---|
| `.txt`, `.md`, `.tex` | как текст (UTF-8 или CP1251) |
| `.docx` | напрямую из ZIP/XML, без внешних библиотек |
| `.doc` | через `antiword` / `catdoc` / LibreOffice |

Если файлов несколько, предпочтение отдаётся файлу с именем `scenario.*`.
`README.md` сценарием не считается.

### Главное правило: служебные слова

**Содержимое всегда начинается с `{`** и читается до **служебного слова,
которое стоит в начале новой строки**. Сбалансированность фигурных скобок
внутри при этом неважна: их может быть сколько угодно, в том числе непарное
число. Закрывающая `}` необязательна — если она есть и стоит в конце
содержимого, она отбрасывается.

Служебные слова: `scene`, `line`, `sub`, `T`, `pause`, `title`,
`author`, `affiliation`, `event`, `date`, `package`/`packages`, `style`,
`common`.

Всё, что стоит вне `{...}` и не начинается со служебного слова, считается
мусором и игнорируется — поэтому в файле могут быть заголовки, комментарии,
пустые строки, пояснения.

Содержимое может быть **многострочным** и содержать любую LaTeX-разметку
(`\frac{a}{b}`, `\\`, `\vspace{}`, `\begin{theorem}...\end{theorem}` и т.п.),
включая непарные `{` и `}` (например, экранированные `\{` и `\}`).

> **Важно.** Внутри `{...}` **нельзя начинать строку со служебного слова**:
> оно оборвёт содержимое. Если такое слово нужно вынести на новую строку,
> оформите его отдельной командой `line`:
>
> ```
> line l1: {первая часть}
> line l2: {line — вторая часть}
> ```

> **Ещё одна мелочь.** Если содержимое само заканчивается на `}`, поставьте
> закрывающую `}` (получится `}}`) или экранируйте нужную скобку: `\}`.

### Пользовательские макросы

Если сценарий — `.tex`-файл, в его преамбуле (до первой содержательной строки
`title` / `common` / `scene` / ...) можно объявлять собственные макросы.
Скрипт переносит их в генерируемую LaTeX-преамбулу, и они работают во всех
строках:

```
\newcommand{\R}{\mathbb{R}}
\newcommand{\norm}[1]{\left\lVert #1 \right\rVert}
\DeclareMathOperator{\E}{E}
\newtheorem{lemma}{Лемма}
\newenvironment{note}{\begin{quote}}{\end{quote}}
\let\oldphi\phi

title: {Презентация}
...

scene: {Сцена}
line l1: {$\R^n$, $\norm{x}$, $\E[X]$, $\oldphi$}
line l2: {\begin{note}Заметка.\end{note}}
line l3: {\begin{lemma}Утверждение.\end{lemma}}
```

Поддерживаются:

- `\newcommand`, `\renewcommand`, `\providecommand` (в том числе `\newcommand*`
  и форма без скобок у имени: `\newcommand\sq[1]{#1^2}`);
- `\DeclareMathOperator` и `\DeclareMathOperator*`;
- `\newtheorem` (с необязательными `[...]`);
- `\newenvironment` и `\renewenvironment`;
- `\let`.

Многократные объявления с аргументами в `[...]` и переносами строк тоже
поддерживаются. Пакеты из `\usepackage{...}` подхватываются автоматически;
`cmap` при этом ставится перед `fontenc`, как требуется.

### Общий блок `common` (необязательно)

Перед титульным слайдом и сценами можно объявить общие строки и субтитры.
Они доступны во всех сценах:

```
common:
line gap: {\vspace{0.5cm}}
sub note: {Общий субтитр.}
```

Блок `common:` — необязательный маркер: все `line`/`sub`/`style`, объявленные
до первой сцены `scene:`, считаются общими. Если в сцене объявить строку с тем
же именем, она переопределит общую.

### Титульный слайд (необязательно)

Перед сценами можно задать титульный слайд. Все поля необязательны; пустое
поле просто не выводится. Если не заполнено ни одно поле, титульного слайда
не будет.

```
title: {Название презентации}
author: {ФИО}
affiliation: {Институт / факультет}
event: {Конференция, семинар, курс}
date: {7 ноября 2026}

pause: 4.0
```

`pause: 4.0` — сколько секунд держать титульный слайд (по умолчанию 4.0).
Оформление: крупное жирное жёлтое название, золотая линия, автор обычным
текстом, организация приглушённым, событие — синим, дата — приглушённым.
Пишите `title:`.

### Элементы

#### scene — новый слайд

```
scene: {Заголовок слайда}
scene: {}
```

Заголовок рисуется сверху, жирным, ярко-жёлтым, без подчёркивания.
Заголовок **необязателен**: `scene: {}` создаёт слайд без заголовка.
Слайды нумеруются по порядку (`Slide00`, `Slide01`, ...).

#### line — строка

```
line l1: {Текст с формулой $\frac{a}{b}$.}
line l2: {$E=mc^2$}
line gap: {\vspace{0.5cm}}
```

`l1`, `l2`, `gap` — произвольные имена (латиница, цифры, `_`, `-`).
Содержимое — любой LaTeX. Строки появляются по центру, одна под другой.

Содержимое может занимать несколько строк и содержать непарные скобки:

```
line note: {Множество $\{x \mid x>0$ — скобки не обязаны быть парными
и это продолжение той же строки}
line next: {...}
```

Здесь `line next:` начинается с новой строки и является служебным словом,
поэтому содержимое `line note` на нём заканчивается. Если бы `line next`
стояло внутри текста (не в начале строки), оно осталось бы частью содержимого.

Особые случаи:

- `line x: {}` — пустая строка: невидимая отбивка (разрыв между блоками).
- `line x: {\vspace{0.5cm}}` — вертикальный отступ заданной высоты.
- Строка без кириллицы автоматически считается формулой и оборачивается
  в математический режим. Строка с кириллицей — текст, формулы внутри неё
  пишите через `$...$`.

#### sub — субтитр

```
sub s1: {Короткая подпись внизу слайда.}
```

Субтитры появляются и исчезают **без анимации**.

#### style — оформление (необязательно)

```
style default: color=TEXT size=36 anim=write align=center
style line l1: color=GOLD
style sub s1: size=24
```

Ключи:

| Ключ | Значения |
|---|---|
| `color` | `TEXT`, `MUTED`, `YELLOW`, `GOLD`, `BLUE`, `GREEN`, `RED`, `PURPLE` или `#RRGGBB` |
| `size` | размер шрифта (число) |
| `anim` | `write` (по умолчанию), `fade`, `none` |
| `align` | `center` (по умолчанию), `left`, `right` |

`style default` задаёт значения по умолчанию для **строк**, `style sub default` —
для **субтитров**, `style line <имя>` и `style sub <имя>` — для конкретной
строки/субтитра. Стили, объявленные в блоке `common:`, действуют во всех сценах.

#### package — дополнительные LaTeX-пакеты

```
package: {amsthm, tikz}
```

Можно также просто писать `\usepackage{...}` в любом месте сценария — скрипт
их найдёт и добавит. Уже подключённые по умолчанию пакеты повторно не
добавляются.

Окружения `theorem`, `lemma`, `definition`, `corollary`, `proposition`,
`remark`, `example` и `proof` доступны сразу (определяются автоматически).

## 5. Таймлайн

Таймлайн — это строки вида `T: <задержка> <действие>` и `pause: <задержка>`.
`timeline:` и круглые скобки **не нужны**.

```
T: 0.5 l1          # через 0.5 с показать строку l1
T: 0.8 s1          # через 0.8 с показать субтитр s1
T: 0.4 l1 -        # через 0.4 с убрать строку l1
T: 0.4 sub: -      # через 0.4 с убрать субтитр
pause: 0.5         # просто подождать 0.5 с
```

Задержка отсчитывается от **предыдущего действия** (от момента, когда оно
завершилось). Действия выполняются по порядку.

Допускается объявление строки прямо в таймлайне (не рекомендуется, но удобно
для мелочей):

```
T: 0.5 line l9: {Появилась прямо здесь.}
```

Аналогично можно объявить и субтитр: `T: 0.5 sub s9: {...}`.

Имя в `T:` может быть как строкой, так и субтитром — скрипт сам понимает по
объявлениям. Если имя не найдено, будет понятная ошибка с номером строки.

## 6. Пример сценария

Короткий пример ниже. Рядом лежит `scenario.tex` — шаблон для быстрого
старта: преамбула с макросами, титульный слайд, `common`, стили и заготовка
сцены; замените содержимое `line l1` своим.

```
# Комментарий. Всё, что вне {...} и не ключевое слово, игнорируется.

common:
line gap: {\vspace{0.5cm}}
sub note: {Общий субтитр.}

title: {Диофантовы уравнения}
author: {Иван Иванов}
affiliation: {МГУ}
event: {Семинар по алгебре}
date: {7 ноября 2026}
pause: 4.0


scene: {Демонстрация}

line l1: {Первая строка с формулой $\frac{a}{b}$.}
sub s1: {Подпись про дроби.}

line l2: {Многострочное содержимое:
\begin{theorem}
Если $a=b$, то $b=a$.
\end{theorem}}

T: 0.5 l1
T: 0.8 s1
T: 0.5 line l3: {Вставленная строка: $x^2+y^2=r^2$.}
T: 0.5 l2
T: 0.3 gap
T: 0.4 note
T: 0.5 l1 -
T: 0.4 sub: -
pause: 0.5


scene: {}

line a: {$E=mc^2$}
T: 0.5 a
T: 0.3 gap
pause: 0.4
```

Этот пример создаёт титульный слайд и два содержательных: первый — с
заголовком и несколькими строками, второй — без заголовка. Общие `gap` и
`note` используются в обеих сценах.

## 7. Ошибки и подсказки

Скрипт старается объяснить, что пошло не так:

| Ситуация | Сообщение |
|---|---|
| нет файла сценария | `в папке нет файла сценария (...)` |
| сценарий не читается | `не удалось прочитать .docx` / `.doc` |
| нет ни одной сцены | `в файле не найдено ни одной сцены вида scene: {...}` |
| `line` до `scene` | `строка объявлена до первой сцены (scene:)` |
| неизвестное имя в `T:` | `неизвестное имя «...» в T:` + номер строки |
| удаление несуществующей строки | `удаляется неизвестная строка «...»` |
| служебное слово в начале строки внутри `{...}` | `ожидалось {...}` + номер строки |
| ошибка LaTeX | `[ОШИБКА] SlideNN` + краткий текст ошибки LaTeX |
| нет доступа к файлу | `Нет доступа к файлу: ...` |

При ошибке LaTeX скрипт печатает имя слайда и суть ошибки (`! ...` и строку
`l.NN`), чтобы можно было быстро найти проблемное место в сценарии.

## 9. Как это работает (кратко)

1. Скрипт находит файл сценария и читает его.
2. Парсит сцены: `title`, `common`, `scene`, `line`, `sub`, `style`,
   `package`, `T`, `pause`.
3. Генерирует вспомогательный `_scenes.py` (классы Manim).
4. Если запрошен PDF — строит `media/handout.tex` и компилирует его.
5. Рендерит слайды параллельно (по 5) в отдельные временные папки.
6. Готовые видео складывает в `media/slides/` и склеивает в `media/final.mp4`.
7. Удаляет всё временное и печатает сообщение о готовности.

Все настройки рендера (качество, FPS, число параллельных процессов) и тема
(цвета, шрифты, размеры) находятся в начале `build.py` в разделах
`1. НАСТРОЙКИ` и `2. ТЕМА`.
